# 人岗匹配校准实验室

对比同一个模型的两种简历初筛流程。A 先做整体判断再补逐项理由，B 先找原文再逐项判定。两组共享岗位标准、简历文本、标签和参数。

首轮题库是按预设岗位规则构造的虚构样例，包含 4 条调试题和 10 条固定对照题，按整组配对分开。样例答案尚未由独立顾问复标。这一轮验证实验能否跑通并定位错误。真实业务效果需要用单独留出的脱敏样本验证。

[首轮对照结果与错因](RESULTS.md) · [第二轮对照与旧题回放](ROUND2.md)

## 验收

1. 同一份简历分别放进两个岗位口径时，判断随实质要求变化。
2. 经历事实相同、表达方式不同，判断保持一致。
3. 区分部分支持、证据不足和明确不符；证据引用能在简历中逐字找到。
4. 保留两版原始判断，分别统计误放、漏聊、待补证和逐项正确数。调用失败单独报数；任一版本缺失时，同一案例不进入成对指标。

## 运行

需要 Node.js 22+，通过环境变量 `DEEPSEEK_API_KEY` 读取凭据。当前命令只发送项目内置虚构文本。

```powershell
node run.mjs --check
node run.mjs --dev
node run.mjs
node run.mjs --round2
node run.mjs --replay
```

`--check` 离线检查题库与指标。`--dev` 只跑调试题，默认跑固定对照题。`--round2` 在 12 条新题上比较 A、B 和 C，C 在 B 的提示词上加入「暂缓须有直接反证」规则。`--replay` 用三版复跑首轮固定对照题，写入独立的 `results/heldout-replay.json`。结果包含模型、请求耗时、逐题结果和错因索引。报告中的「建议约聊」是实验标签，实际是否推进由顾问决定。
